story 212
Acceptance Criteria
Every value arriving from outside is bound as a JDBC bind parameter; the harness fails the build on any string interpolation in a mapper.

Result sets map cleanly onto the domain and DTO objects.

Tasks
Write the mappers in XML under src/main/resources/mapper/ or in annotations on the mapper interface; either style is acceptable.

Bind the account key, the symbol, the status filter and the timestamps as parameters, never as text substituted into the statement.

If a column name or sort direction genuinely cannot be a bind parameter, check it against a fixed list of permitted names first and declare it in the manifest allowlist with a comment saying what does that checking.

Unit Test Execution Paths

Notes
A symbol of AAPL' OR '1'='1 substituted into a statement becomes part of that statement, and the positions that come back are whichever account the attacker asked for. That is OWASP A03.

An allowlist entry is a question the review asks.

story 213
Acceptance Criteria
Order placement is transactional, so cash and position move together or neither moves.

The update names the version the account row held when it was read and increments it; zero rows affected is refused with ORD-409 rather than treated as success.

Tasks
Annotate the order placement path with @Transactional and keep the transaction around the work that has to be atomic and no more.

Read the version with the row and return the affected row count from the mapper, because a mapper returning void has thrown away the only evidence that anything happened.

Make the cancel transition conditional on the state you expect, in one statement.

Unit Test Execution Paths
place order commits cash and position together

failed order rolls back with no partial write

a concurrent update is detected and the second writer is refused

cancelling a filled order returns ORD-409

Notes
Without the lock, two buys of 20,000 against a balance of 25,000 both read the row, both write the same figure back, and nothing reports it until somebody reconciles the cash the next morning.

story 215
Acceptance Criteria
A @ControllerAdvice maps every domain exception to its documented code and HTTP status, with no stack trace or internal detail in the body.

The message is written for a human reading a screen: no class name, no SQL fragment, no account key, no internal identifier.

Tasks

Log what an investigation needs on the server rather than returning it.

Confirm that clients can branch on the code, since 404 and 409 each carry more than one code.

story 216
Acceptance Criteria
Every route under the API prefix is answered for token validity once, before any controller runs.

A missing header, a wrong scheme, an expired token and a forged signature all return AUTH-401 with the same body.

A token that does not reach the addressed account returns ACC-403 with the same message a suspended account gets.

Tasks
Check the signature, the expiry and the algorithm the token asks for, in that order, before reading a claim.

Read the demo users, the claims and the shared signing secret from services/auth-stub/README.md; the stub starts with the infrastructure.

Answer authorisation where the account key is known, not in the filter.

Notes
A verifier that decodes the payload first has already trusted whatever the client sent.

A more specific message tells an attacker which of the four failures they got, and the identical ACC-403 message stops anyone enumerating account keys.

Sprint 8 swaps the stub for the real service as a configuration change. If yours needs a code change, something is coupled to the stub rather than to the token, and that is worth finding now.

story 217
Acceptance Criteria
The service builds and runs from a multi-stage Dockerfile whose final stage is not a build image and does not run as root.

docker compose up -d --profile platform starts the service, which resolves postgres and the auth stub by service name and reports healthy.

Tasks
Build the jar in a stage carrying Maven and a JDK, and take it into a stage carrying a Java runtime and neither of the other two.

Order the copies so that changing a source file does not invalidate the resolved-dependency layer.

Build both projects inside the image build, because it starts with an empty local Maven repository and cannot reach the Sprint 5 module on your laptop.

Add the service to the root docker-compose.yml under the platform profile, on trading-net, with a published port, database and JWT_SECRET values from the environment, depends_on Postgres on its health condition, and a health check.

Notes
Every tool in an image is a tool available to whoever gets into the container, which is the reason to care rather than disk.

Nothing this sprint needs Kafka.
